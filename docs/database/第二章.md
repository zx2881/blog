# 2.关系数据库

## 2.1 关系数据结构及形式化定义

- 简介
    - 一个关系就是一个表
    - 关系模型就是处理表的，由三个部分组成：
        - 描述数据库各种数据的基本结构形式
        - 描述表与表之间所有可能的各种操作
        - 描述这些操作所应遵循的约束条件

### 2.1.1 关系

关系模型只包含单一的数据结构－－关系，并且它的逻辑结构就是一张二维表。

- 基本概念
    
    - 域（domain）：一组具有相同数据类型的值的集合 （就是表中的一列）
    - 笛卡尔积
        - 定义：给定一组域d1，d2，d3，允许其中某些域是相同的，他们的笛卡尔积就是不同组合
        - 元组(tuple)：笛卡尔积里面的每个元素
        - 分量：元组里面的每个值
        - 基数：一个域中允许的不同取值的个数
    - 关系
        - 定义：笛卡尔积的一个子集
        - 元组：关系中的每个元素 （即：表中的一行）
        - 单元关系与二元关系：n＝1为单元／一元关系，n＝2为二元关系
        - 关系就是一张二维表
        - 属性：关系中不同列可以对应相同的域，为了区分必须给每列起一个名字。（就是表中竖着那一列的表头）
        - 码（key）
            - 候选码：关系中的一个属性组能够唯一地识别一个元组；如果所有属性组成候选码，称为全码（all－key）
            - 主码：若一个关系有多个候选码，则其中一个为主码
            - 主属性：候选码的诸属性
            - 非主属性：不是候选码的诸属性
        - 三种类型的关系
            - 基本关系（表）：实际存在的表，是实际存储数据的逻辑表示；
            - 查询表：查询结果对应的表；
            - 视图表：由基本表或者其他视图表导出的表，是一个虚表，不对应实际存储的数据
            - **视图表不一定和查询表对应**
        - 关系的性质
            - 列是同质的；
            - 不同列可出自同一个域
            - 行，列的顺序无所谓；
            - 任意两个元组的候选码不能相同
            - 分量必须取原子值（即表中不能有表）
    
    ## 2.1.2 关系模式
    
    - 关系模式（表头）：静态的，稳定的
    - 关系（元组）：动态的
    
    ## 2.1.3 关系数据库
    
    - 在一个给定的应用领域，所有关系的集合构成一个关系数据库
    - 关系数据库的型：是对关系数据库的描述
    - －－－－－－的值：关系模式在某一时刻对应的关系的集合
    
    ## 2.1.4 关系模型的存储结构
    
    - 关系数据库的物理组织
        - 一个表对应一个操作系统文件，将物理数据组织交给操作系统（）

## 2.2 关系操作

### 2.2.1 基本的关系操作

- 常用的关系操作
    
    - 查询操作：选择、投影、连接、除、并、差、交、笛卡尔积、
    - 5种基本操作：投影、选择、并、差、笛卡尔积
- 数据更新
    
    - 插入、删除、修改
- 关系操作的特点
    
    属于集合操作方式，操作的对象和结果都是集合
    

### 2.2.2 关系数据语言的分类

- 关系代数语言（例：ISBL）
    
    用对关系的运算来表达查询要求
    
- 关系演算语言
    
    - 用谓词来表达查询要求
    - 元组关系演算语言：谓词变元的基本对象为
    - 域关系演算语言
- 双重特性
    
    - SQL

## 2.3 关系的完整性

- 三类完整性约束：**实体完整性、参照完整性**、用户自定义的完整性

### 2.3.1 实体完整性

- 规则
    
    - 2.1： 主属性不能取空值
    
    > 例：学生（**学号**，姓名，性别，）
    

### 2.3.2 参照完整性

#### 1.关系间的引用

例：学生实体与专业实体

学生（**学号**，性别，姓名，**专业号**，年龄）

专业（**专业号**，专业名）

例：学生、课程、学生与课程之间（多对多）

学生（**学号**，姓名，性别，专业号，年龄）

课程（**课程号**，课程名，学分）

选修（**学号，课程号**，成绩）

例：学生实体内部 一对多

学生（学号，姓名，性别，专业号，年龄，**班长**）

#### 2.外码

专业号 属于 学生关系 的 外码

专业关系是被参考的关系，学生关系为参考关系

学生关系和课程关系均为被参考关系

选修关系为参考关系

班长是外码

学生关系既是参考系也是被参照关系

### 2.3.3 用户定义的完整性

- 针对某一具体关系数据库的约束条件，与现实应用有关
- 例：学生成绩取值在0－100之间
